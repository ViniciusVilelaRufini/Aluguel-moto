# Plano da área — API NestJS (Task 3, agente 2 parte B)

> Executado com TDD (superpowers:test-driven-development). Cada regra de negócio: teste vermelho → implementação mínima → verde → refatorar.

**Goal:** implementar em `services/api` as 140 operações do `packages/contracts/openapi.yaml` aprovado, com Prisma/PostGIS, Redis, portas para IoT/cobrança/seguro (stubs), WebSocket `/realtime`, seed de São Paulo, e2e do fluxo do aluguel e teste de contrato.

**Stack (plano mestre):** Node 24, NestJS 10.4, Prisma 5.22, PostgreSQL 16 + PostGIS 3.4, Redis 7 (ioredis), Socket.IO 4, `@nestjs/event-emitter`, `@nestjs/throttler`, `@nestjs/schedule`, class-validator, jose, AWS SDK v3 (S3/SQS), Jest 29 + supertest + jest-openapi.

- Segurança por padrão: guard global; rota sem `@Auth(...)` nem `@Public()` é negada. `@Auth('customer')`, `@Auth('staff', grupos)`, `@Auth('any', grupos)` espelham `security` + `x-required-groups`.
- Erros: `ProblemException(status, slug, detail)` → filtro global gera `application/problem+json` com `type = https://api.volti.com.br/problems/<slug>`. `ValidationPipe` → 400 `validation-error` com `errors[]`; throttler → 429 `rate-limited` + `Retry-After`.
- Idempotência: `@Idempotent({ required })` → interceptor grava `(escopo, chave, hash do corpo, status, corpo)` por 24 h; repetição devolve a mesma resposta; corpo diferente → 422 `idempotency-key-reused`; ausente quando obrigatório → 400.
- Rotas literais (`/vehicles/nearby`, `/vehicles/by-code/:code`, `/rentals/current`, `/payments/cards` …) declaradas antes de `/:id`; `:id` com `ParseUUIDPipe`.
- Eventos internos do plano mestre consumidos em realtime, alerts, rentals, commands e vehicles; eventos próprios (`vehicle.status-changed`, `command.changed`, `alert.created`, `rental.changed`, `zone.changed`, `reservation.ended`) alimentam o WebSocket e os módulos das Tasks 4/5.
- Jobs (`@nestjs/schedule`): expiração de reservas (TTL do Redis + varredura), retentativa de encerramento `ending`, `rental.updated` a cada 30 s, apagar `TrackPoint` expirado (diário), "você está bem?" sem resposta em 60 s. Desligáveis por `JOBS_ENABLED=false` (testes).

## Banco (Prisma)

Modelos: Customer, StaffUser, Device, Vehicle, Tracker, Battery, Zone (`geom geometry(Polygon,4326)` + GeoJSON), PricingPlan, Coupon, CouponRedemption, Fee, Reservation, Rental, RentalEvent, Payment, Deposit, PaymentCard, Subscription, WalletEntry, TopUp, MinutePackage, InsuranceCoverageConfig, InsurancePolicy, Incident, Dispute, Claim, SupportConversation, SupportMessage, MaintenanceTask, FieldTask, Inspection, BatterySwap, Alert, AuditLog, VehicleCommand, TrackPoint (índice em `expiresAt`), RestrictionEntry, IdempotencyRecord, LocationShare.
Migração inicial gerada por `prisma migrate diff` + SQL manual: extensão PostGIS, índice GIST das zonas e da posição das motos, índice único parcial "uma reserva ativa por cliente" e "um aluguel em andamento por cliente/moto".

Seed: 60 motos `VLT-0001…0060` (`moto-0001…`), zona `operation` (Pinheiros/Vila Madalena/Paulista), 6 `return`, 1 `forbidden` (Ibirapuera), 2 `reduced_speed` (calçadão 6, ciclovia Faria Lima 20), planos/taxas/seguros/pacotes da tabela de preços, staff dev de cada grupo, 2 clientes (aprovado e pendente).

## Ordem TDD (testes obrigatórios do brief)

1. **pricing** — `pricing.service.spec.ts`: minute 10 min → 1090; 10:01 → 1169; +5 min pausa → 1190; cupom 20 % → 872; hour 61 min → 5800; day 25 h → 17800; encerramento soma seguro basic +200.
2. **auth** — `auth.guard.spec.ts` (HTTP com app de teste): token de cliente em rota de staff → 403; `financeiro` em `POST /vehicles/{id}/commands` → 403; sem token → 401.
3. **commands** — `commands.service.spec.ts` + HTTP: `speed_limit` 33 → 400 e `IotGateway` não chamado; `reason` vazio → 400; todo comando grava AuditLog.
4. **reservations** — `reservations.service.spec.ts`: segunda reserva → 409; TTL curto expira e libera a moto.
5. **rentals start** — `rental-start.service.spec.ts` + HTTP de idempotência: KYC → 403; inadimplente → 403; mesma chave → um aluguel e mesma resposta; moto indisponível → 409.
6. **rentals end** — `rental-end.service.spec.ts`: fora de zona → 422 `rental-outside-return-zone`; sem foto → 422; sem confirmação → `ending` + retentativa; confirmado → `ended` e `settle` uma vez; `force-end` sem `reason` → 400; fora da zona soma 1500.
7. **lgpd** — `lgpd.service.spec.ts`: export só do próprio cliente; exclusão anonimiza e mantém pagamentos; job apaga `TrackPoint` expirado.
8. Demais módulos: implementação direta com validação, mapeadores para o contrato e testes pontuais (zonas 21–32 → 422, inspeção > 32 com `ok: true` → 422).
9. **e2e** `test/rental-flow.e2e-spec.ts` (Postgres/Redis do compose): dev token → reserva → aluguel → pausa → retoma → foto → encerra → `ended` com `costCents` correto.
10. **contrato** `test/contract/*.contract-spec.ts` (`pnpm --filter api test:contract`): sobe a API e valida 10 endpoints com jest-openapi.
